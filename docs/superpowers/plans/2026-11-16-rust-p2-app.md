# P2 — Tauri app (in progress)

> Companion of the P0/P1 plans. All code, comments and tests are in English;
> UI strings go through `rust/web/src/i18n.tsx` (es/en).

## Done (verified)

- `sqlt-app` connection store: JSON metadata in the OS config directory, passwords
  only in the OS keyring (`com.sqltools.rust`). Tests assert the JSON never
  contains a `password` field.
- Tauri commands: list/save/delete connections, connect/disconnect, execute with
  streaming `Channel`, cancel, commit, rollback, history, object names for
  autocomplete, explain plan.
- CodeMirror 6 editor: SQL language, line numbers, folding, search, multiple
  selections, active line, bookmark gutter (click to toggle), keyword/table
  autocomplete, `Mod-Enter` executes the selection or the whole document.
- Results: streamed batches appended to React state, virtualized table (fixed row
  height + spacers; only the visible window is rendered), CSV export of all
  fetched rows.
- Bookmarks are a `RangeSet<GutterMarker>` and map through edits automatically.
- **Multi-statement execution**: `sqlt_app::script::run_script` splits the buffer
  with `sqlt_core::split`, sends SELECT/WITH statements through the streaming
  query path and everything else (DML/DDL/PL-SQL) through `Session::execute`,
  stopping on the first error. `Mod-Enter` with no selection and
  `Script.ExecuteCurrent` pass the cursor offset and run only the statement
  under the cursor. Each result set replaces the grid (last statement wins).
  Integration covers `select 1; select 2` (2 result sets, 2 rows), statement at
  cursor and an anonymous block.
- Live regression test: a script with two SELECTs used to be sent to Oracle as
  one statement and fail; now it runs statement by statement.
- **Value mapping**: NUMBER kept as text, dates/timestamps with the local fast
  formatter for English NLS (driver format otherwise), RAW/BLOB/LONG RAW as
  bytes, CLOB/NCLOB by locator, JSON, XMLTYPE, Oracle `Object`/`Collection` via
  their `Display` form (`SYS.ODCIVARCHAR2LIST("a", "b")`) and REF CURSOR as the
  `(REF CURSOR)` placeholder (no nested result sets in the grid). A budget is
  applied **before** materializing: collections over 50 elements (or with LOB
  or XML/JSON/nested-object elements) become `SYS.TYPE(N element[s])`, objects
  with more than 50 attributes or any LOB/XML/JSON/nested-object attribute
  become `SYS.TYPE(...)`
  (the crate renders nested objects with a full `to_string()` before any writer
  sees them), and `Display` itself is capped at 4 KB per cell through a budget
  writer (which also covers 32,767-byte `VARCHAR2` values under
  `MAX_STRING_SIZE=EXTENDED`). Integration tests use
  the built-in `SYS.ODCIVARCHAR2LIST`, `SYS.ANYDATA`, `COLLECT(...)` cast to
  `SYS.ODCINUMBERLIST` and a SQL cursor expression, so no user types are
  created.
- History panel (in-memory, last 2000), plan panel, **session statistics**
  (`V$MYSTAT`/`V$STATNAME`), status bar, i18n es/en.
- **Object explorer**: schema/type filter, object list, columns for tables/views,
  **Load DDL** through `DBMS_METADATA.GET_DDL`.
- End-to-end backend tests (`cargo test -p sqlt-app --test app_integration --
  --ignored`) against Oracle 12.1 via keyring: connect, query `dual`, delete the
  stored password, 1000 table names, columns, DDL and 117 session stats.
- Desktop smoke: `cargo build -p sqlt-desktop` and the app stays running.

- [x] `Session.EnableDbmsOutput`: `Session::enable_dbms_output` and
  `dbms_output_lines` drain the **whole** `DBMS_OUTPUT` buffer with real OCI OUT
  binds (`OracleType::Varchar2(32767)` for the buffer, NUMBER for the status;
  the line is read only when the status is 0), keep at most `max` lines and
  append `-- N more DBMS_OUTPUT lines were truncated` when the rest was
  dropped. Draining is auxiliary, so `DBMS_OUTPUT.DISABLE` inside a script (or
  any `GET_LINE` failure) ends the drain instead of failing the statement.
  When a statement fails after printing, `run_script` discards its buffer
  before returning the error, so the lines cannot leak into the next execution.
  `Session::lock_execution` serializes whole script cycles per OCI session
  (`run_script` holds it from the first statement to the last drain); the Tauri
  `commit`, `rollback` and `enable_dbms_output` commands wait for the same guard
  in `spawn_blocking` (so they cannot land mid-script or freeze the UI), while
  `cancel` deliberately does not take it and keeps interrupting the running
  statement. `connect`/`disconnect` mark the session closed, cancel it and wait
  for the execution guard before dropping or replacing it (`spawn_blocking`, so
  the UI stays responsive); `run_script` re-checks `is_closed()` before every
  statement and before every fetch batch (a callback can close the session when
  no OCI call is active), stops the `DBMS_OUTPUT` drain as soon as the session is
  closed, skips draining an already-closed session, and re-checks after the
  drain and after the last statement so a close never ends as a successful run.
  The UI ignores a second `run()` while one is active and disables
  Commit/Rollback during execution, so concurrent executions cannot interleave
  result sets or output. `run_script` emits one
  `ScriptEvent::Output(Vec<String>)` per drained batch, the Tauri channel maps
  it to `QueryEvent::Output`, and the UI appends it to a new Output panel (the
  panel opens automatically). Verified against Oracle 12.1 by the crate tests

  not fatal; 1005 lines → 1000 kept + truncation marker, buffer consumed), by
  the app integration tests (script run emits `from script`; a later
  `dbms_output.disable` script still succeeds; a failed block that printed is
  discarded and the next query emits nothing; a second thread cannot take the
  execution lock until the first releases it; `disconnect` while a guard is held
  does not return until it is released; a closed session rejects `run_script`;
  closing from the Output callback runs only the first statement; closing from
  the first Batch callback fetches no second batch and fails with the closed
  message; closing from the only Output callback still delivers the lines but
  the run fails) and by CDP on the real app:
  `235/150` commands, palette → Enable Dbms Output → run a PL/SQL block →
  Output tab with `hello from dbms_output` / `second line`, status `1 row · 19
  ms`. Together with XMLTYPE (which maps to `Value::Text` and is covered by
  `xmltype_maps_to_text`), this closes the OUT-bind gap.

## UI port to the original SQLTools look (2026-11-16)

The first React UI was functional but visually unrelated to the C++/Qt original.
Reference: `docs/manual/img/01_ventana_principal.png`, `02_resultados_salida.png`,
`07_paneles_laterales.png` (shipped with the repo).

- Light classic theme (`#f0f0f0` panels, `#a0a0a0` borders, white editor/grid),
  Segoe UI 12px, Consolas 13px in the editor; CodeMirror default light theme.
- Two dense toolbars: inline SVG icons (16px, stroke) with title/aria-label for
  run, cancel, commit, rollback, format, history, plan, stats, export, workspace
  save/open, command palette, update check, connect/disconnect, refresh and the
  connection-settings toggle; compact connection select, read-only check,
  language select and a connection chip.
- Left `Objetos` panel: schema and name filters, object-type button grid
  (All/Tables/Views/Packages/Procedures/Functions/Triggers/Sequences), and a
  `Nombre/Tipo` grid with hover/selection and the existing context menu.
- Workspace: editor tab (`SQL` + `user@alias`), dense panel tabs
  (Resultados/Historial/Plan/Objeto/Estadísticas), export/clear icons, grid with
  a row-number column (kept `ROW_HEIGHT = 24` and updated spacer `colSpan`), and
  a two-sided status bar (query metrics left, connection right).
- Connections form moved into a collapsible section below the object list; it
  auto-opens only when no connection is configured and collapses after
  save/connect.
- Command palette hides unnamed registry entries before filtering and paging;
  it now lists friendly names, shortcuts and `No implementado`.
- `tauri.conf.json` no longer sets `devUrl`: any debug build loads the embedded
  `web/dist` instead of `http://localhost:1420`, which was the cause of the
  blank window with "localhost refused the connection". `beforeBuildCommand`
  (`npm --prefix web run build`, CWD `rust/`) keeps `npx tauri build`
  self-sufficient.
- Verified by driving the real app through the WebView2 CDP endpoint
  (`--remote-debugging-port=9222`): filled the connection form, saved it
  (keyring), connected to Oracle 12.1, loaded 2700 objects, ran
  `select * from dual` (1 fila · 3 ms) and a two-statement script (last result
  set wins, `1 fila · 3 ms`). Screenshots: `docs/screenshots/current-*.png`.
