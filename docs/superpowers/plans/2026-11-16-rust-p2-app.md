# P2 — Tauri app (in progress)

> Companion of the P0/P1 plans. All code, comments and tests are in English;
> UI strings go through `rust/web/src/i18n.tsx` (es/en).

## Done (verified)

- `sqlt-app` connection store: JSON metadata in the OS config directory, passwords
  only in the OS keyring (`com.sqltools.rust`). Tests assert the JSON never
  contains a `password` field.
- Tauri commands: list/save/delete connections, connect/disconnect, execute with
  streaming `Channel`, cancel, commit, rollback, history, object names for
  autocomplete, explain plan.
- CodeMirror 6 editor: SQL language, line numbers, folding, search, multiple
  selections, active line, bookmark gutter (click to toggle), keyword/table
  autocomplete, `Mod-Enter` executes the selection or the whole document.
- Results: streamed batches appended to React state, table shows the first 500
  of the fetched rows; CSV export.
- History panel (in-memory, last 2000), plan panel, status bar, i18n es/en.
- End-to-end backend test (`cargo test -p sqlt-app --test app_integration --
  --ignored`) against Oracle 12.1 via keyring: connect, query `dual`, delete
  the stored password.
- Desktop smoke: `cargo build -p sqlt-desktop` and the app stays running.

## Pending for P2

- Session statistics (`V$MYSTAT` before/after) and an Output/Errors panel.
- Full result virtualization (the grid currently renders 500 rows; batches are
  already streamed) and export of the complete result set from Rust.
- Bookmark positions currently clear on edit; map them through changes.
- Column autocomplete for `alias.`/`table.` (needs the SQL context port).
- Multiple script tabs, recent files, unsaved-changes prompt.
- Connection import from Windows SQLTools `connections.xml`.
- DDL/Object Viewer are P3, not P2.
